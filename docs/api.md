# API reference

The deployed API is AWS AppSync GraphQL, generated by Amplify Gen 2 from
[`apps/web/amplify/data/resource.ts`](../apps/web/amplify/data/resource.ts). This page documents
the stable application-facing contract. Generated TypeScript clients remain the source of truth
for exact generated CRUD input and selection-set types.

## Authentication modes

The default authorization mode is Cognito User Pools. Custom operations use these modes:

| Mode                                 | Callers                                             | Notes                                                                                                                                    |
| ------------------------------------ | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Cognito User Pool                    | Signed-in users with the operation's required group | The default mode for staff operations.                                                                                                   |
| Cognito Identity Pool, authenticated | Signed-in web/mobile reporting clients              | Clients explicitly pass `authMode: 'identityPool'` for submission and media upload.                                                      |
| Cognito Identity Pool, guest         | Anonymous reporting clients                         | Allowed only on submission and media upload.                                                                                             |
| IAM resource access                  | `classify-report` worker                            | Used for the worker's `publishReportUpdate` call. The schema-level grant covers mutation operations, not arbitrary external IAM callers. |

Authorization failures rejected by AppSync before Lambda invocation use AppSync's standard
`Unauthorized` error rather than an application error prefix.

## Custom operations

### `submitReport` mutation

Durably creates a `NEW`, version-1 report, its opening `SUBMITTED` audit event, and a 24-hour
idempotency record in one DynamoDB transaction.

**Authorization:** Cognito User Pool, authenticated Identity Pool, or guest Identity Pool.

| Argument          | Type       | Required | Contract                                                                        |
| ----------------- | ---------- | -------- | ------------------------------------------------------------------------------- |
| `text`            | `String`   | yes      | Trimmed; 1–5,000 characters. Treat as untrusted input.                          |
| `clientRequestId` | `String`   | yes      | Non-blank idempotency key. Reusing it returns the originally created report.    |
| `lat`, `lng`      | `Float`    | no       | Must be supplied together; latitude is `[-90, 90]`, longitude is `[-180, 180]`. |
| `regionId`        | `ID`       | no       | Optional client-supplied operational region.                                    |
| `isAnonymous`     | `Boolean`  | no       | When true, reporter identity and contact are discarded even if supplied.        |
| `reporterContact` | `String`   | no       | PII; never sent to AI prompts or public projections.                            |
| `mediaKeys`       | `[String]` | no       | Up to ten keys returned by `createMediaUploadUrl`.                              |

**Returns:** `Report`. The initial response has `status: NEW`, `version: 1`, and matching
`createdAt`/`updatedAt`. `reporterId` is never a client argument: the resolver derives it only
when AppSync presents a Cognito User Pool identity. Identity Pool and guest calls do not expose a
User Pool `sub` to this handler, so their stored `reporterId` is null.

**Errors:** deterministic input rejections use the stable `VALIDATION:` prefix; clients may strip
the prefix for display and must not retry the same rejected input unchanged. Other DynamoDB
failures propagate unless they are an idempotent-replay signal (`TransactionCanceledException` or
`IdempotentParameterMismatchException`) and the original report can be loaded.

### `createMediaUploadUrl` mutation

Creates a five-minute presigned S3 POST. It does not upload the file; the caller must construct a
multipart form from the returned fields, append the file last, POST it, then pass the returned
`key` to `submitReport.mediaKeys`.

**Authorization:** Cognito User Pool, authenticated Identity Pool, or guest Identity Pool.

| Argument          | Type     | Required | Contract                                                       |
| ----------------- | -------- | -------- | -------------------------------------------------------------- |
| `clientRequestId` | `String` | yes      | Non-blank; scopes the object under `reports/<request-id>/...`. |
| `contentType`     | `String` | yes      | `image/jpeg`, `image/png`, or `image/webp`.                    |

**Returns:** `{ url: String!, fields: AWSJSON!, key: String! }`. Depending on generated-client
version, `fields` may arrive as an object or a JSON string; use `parseMediaUploadFields` from
`@crisismap/shared`. The signed S3 policy enforces a 1-byte to 10-MiB size range and the requested
content type.

**Errors:** invalid arguments raise `MediaUploadValidationError`; STS/presigning failures
propagate. No stable application error prefixes are defined.

### `updateReportStatus` mutation

Applies one human-driven state transition with role authorization and optimistic locking, then
atomically appends a `STATUS_CHANGED` audit event.

**Authorization:** `RESPONDER`, `COORDINATOR`, or `ADMIN` Cognito group. When a token has several
application groups, the resolver uses the highest-ranked role.

| Argument          | Type     | Required | Contract                                             |
| ----------------- | -------- | -------- | ---------------------------------------------------- |
| `reportId`        | `ID`     | yes      | Existing report id.                                  |
| `toStatus`        | `String` | yes      | Must be a legal next status in `STATUS_TRANSITIONS`. |
| `expectedVersion` | `Int`    | yes      | Version last read by the caller.                     |
| `note`            | `String` | no       | Trimmed and stored in the audit-event detail.        |

**Returns:** the updated `Report`; `version` is `expectedVersion + 1` and `updatedAt` is advanced.

**Stable error prefixes:**

| Prefix                | Meaning                                                    | Caller action                                      |
| --------------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| `NOT_FOUND:`          | No report exists for `reportId`.                           | Remove/refetch the item.                           |
| `ILLEGAL_TRANSITION:` | The state-machine edge does not exist.                     | Do not retry unchanged.                            |
| `FORBIDDEN:`          | The caller's effective role cannot perform the legal edge. | Escalate or choose an allowed action.              |
| `CONFLICT:`           | The read version or conditional write is stale.            | Refetch, reassess, and retry with the new version. |

### `listVolunteerTasks` query

Returns the read-only volunteer board projection by joining a bounded working set of reports,
assignments, and teams inside the resolver.

**Authorization:** `VOLUNTEER`, `RESPONDER`, `COORDINATOR`, or `ADMIN` Cognito group.

**Arguments:** none.

**Returns:** `[VolunteerTask!]!`, with these fields:

`reportId`, `status`, `category`, `urgency`, `priorityScore`, `priorityBand`, `summary`,
`regionId`, `createdAt`, `assignmentId`, `assignmentStatus`, `teamId`, `teamName`, and `column`.

The response has no fields for raw report text, reporter identity/contact, media, internal notes,
or precise coordinates/geohashes. The resolver scans at most 250 rows from each backing table and
does not paginate; this is an explicit MVP bound.

### `publishReportUpdate` mutation

Echoes a redacted `PublicReport` projection through AppSync so subscriptions can fan it out. It
does not persist data and publish failure never rolls back the worker's durable write.

**Authorization:** the intended caller is the `classify-report` worker using its schema-level IAM
resource grant. `ADMIN` User Pool access also exists because Amplify Gen 2 requires a per-operation
authorization rule on every Lambda-backed custom operation; clients should not use that door.

**Arguments:** `reportId` and `status` are required. Optional public fields are `category`,
`urgency`, `priorityScore`, `priorityBand`, `summary`, `lat`, `lng`, `geohash`, `geohashPrefix`,
`regionId`, `createdAt`, and `updatedAt`.

**Returns:** `PublicReport`, containing exactly those public fields. Omitted optional values are
normalized to null. The type has no wire representation for PII or raw report text.

Custom subscriptions consuming this mutation are disabled pending CRIS-28, so the mutation
currently has no subscribers.

## Generated model operations

Amplify generates create/get/list/update/delete operations plus the listed secondary-index
queries. These operations have coarse model authorization and are not substitutes for guarded
custom mutations.

| Model               | Cognito access                                                          | Secondary-index queries / notes                                                                                                                                                  |
| ------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Report`            | `COORDINATOR`/`ADMIN`: CRUD; `RESPONDER`: read                          | `reportsByRegion`, `reportsByCategory`, `reportsByStatus`, `reportsByGeohash`, `reportsByDuplicateGroup`, `reportsByTeam`. Contains PII; citizens and volunteers cannot read it. |
| `ReportEvent`       | `COORDINATOR`/`ADMIN`: read/create; `RESPONDER`: read                   | `eventsByReport`. Treat as append-only even though generated schema details may expose more.                                                                                     |
| `Verification`      | `COORDINATOR`/`ADMIN`: CRUD; `RESPONDER`: read/create                   | `verificationsByReport`.                                                                                                                                                         |
| `DuplicateGroup`    | `COORDINATOR`/`ADMIN`: CRUD; `RESPONDER`: read                          | No secondary query.                                                                                                                                                              |
| `Assignment`        | `COORDINATOR`/`ADMIN`: CRUD; `RESPONDER`: read/update                   | `assignmentsByTeam`, `assignmentsByReport`.                                                                                                                                      |
| `Team`              | `COORDINATOR`/`ADMIN`: CRUD; `RESPONDER`: read                          | `teamsByRegion`.                                                                                                                                                                 |
| `AlertSubscription` | Owner in `userId`: owner-scoped operations; `COORDINATOR`/`ADMIN`: read | `subscriptionsByRegion`, `subscriptionsByUser`. Alert dispatch is deferred.                                                                                                      |
| `AlertDelivery`     | `COORDINATOR`/`ADMIN`: read                                             | `deliveriesByReport`. Citizen alerts are deferred.                                                                                                                               |
| `Region`            | `ADMIN`: CRUD; any authenticated user: read                             | No secondary query.                                                                                                                                                              |
| `CategoryConfig`    | `ADMIN`: CRUD; any authenticated user: read                             | No secondary query.                                                                                                                                                              |
| `IdempotencyRecord` | `ADMIN`: read                                                           | `idempotencyByKey`; application code owns writes and TTL behavior.                                                                                                               |

## Known wire-contract quirks

- Amplify adds non-null `updatedAt` fields to models. Some `ReportEvent` rows written directly by
  transition/classification code do not contain `updatedAt`; reads of those rows must use an
  explicit selection set that omits `updatedAt`. `useIncidentTimeline` demonstrates the supported
  selection.
- Generated model mutations coexist with guarded custom operations. Use `submitReport` for report
  creation and `updateReportStatus` for human status changes so idempotency, version checks, and
  audit events cannot be bypassed accidentally.
- The API has no active custom subscriptions until CRIS-28. Dashboard and volunteer reads are
  refresh/one-shot paths today.

## Integration testing

Handler-level integration tests run under normal `npm test` with fake AWS SDK boundaries. The live
suite exercises Cognito, AppSync, Lambda, DynamoDB, and S3 against a deployed personal sandbox,
including User Pool and both guest/authenticated Identity Pool authorization paths.

Start the sandbox in one terminal:

```bash
cd apps/web
npx ampx sandbox
```

Then run the suite from the repository root in a second terminal:

```bash
CRISISMAP_INTEGRATION_TARGET=personal-sandbox npm run test:integration
```

The live suite refuses to run without that exact opt-in value. It creates temporary Cognito users
and best-effort deletes users and generated model fixtures. Append-only `ReportEvent` and
`IdempotencyRecord` rows remain until their normal lifecycle removes them, and the media smoke
object may remain. Never point the suite at a shared environment.
